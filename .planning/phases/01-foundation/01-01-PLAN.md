| Boundary | Description |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `deleteCreative` blob+row cleanup | mitigate | Delete blobs BEFORE the DB row; on `del()` failure the row remains (orphaned-row is recoverable, orphaned-blob is not). `del()` no-ops on missing blobs. |
| T-01-02 | Information Disclosure | `BLOB_READ_WRITE_TOKEN` | mitigate | Documented only in `.env.example` (no value); never placed in a `NEXT_PUBLIC_*` var; `creatives.ts` is server-only (imports `@vercel/blob` + prisma — not importable from client components). |
| T-01-03 | Elevation of Privilege | `del()` full-store delete authority | accept (Phase 1) / transfer (Phase 2) | No caller invokes `deleteCreative` in Phase 1 (no routes/UI). Phase 2 admin routes MUST verify `isAdminAuthenticated()` before calling it — recorded as a Phase 2 obligation in 01-RESEARCH.md Security Domain. |
| T-01-04 | Tampering | Input Validation (MIME/size) | accept (Phase 1) | Constants are DEFINED here but enforcement is Phase 2 (D-07). The data layer is intentionally thin; no untrusted input reaches it in this phase. |
| T-01-SC | Tampering | `npm install @vercel/blob` | mitigate | Package vetted in 01-RESEARCH.md Package Legitimacy Audit — Vercel-org official SDK, ~3yr old, 4.2M wk downloads.
