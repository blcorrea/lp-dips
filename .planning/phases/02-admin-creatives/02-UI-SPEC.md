# Phase 2 — UI Design Contract: Admin Creatives

> Visual and interaction contract for the admin Affiliate Creatives management surface.
> Generated by gsd-ui-researcher. Consumed by gsd-ui-checker, gsd-planner, gsd-executor, gsd-ui-auditor.

**Scope:** Admin management surface only (`/admin/creatives`). The affiliate-facing glassmorphism gallery (Phase 3) is explicitly out of scope here. The admin UI uses the existing plain admin style — no glassmorphism, no brand colors, no storefront fonts.

## Spacing Scale

All spacing values are multiples of 4. These mirror the existing admin conventions extracted from `AffiliatesTable.tsx` and `page.tsx`.

| Token | Value | Admin Usage |
|-------|-------|-------------|
| xs | 4px | Icon-to-label gap, badge horizontal padding (`px-2 py-1`) |
| sm | 8px | Button internal padding (`py-2`), stat card label-to-value gap (`mt-1`) |
| md | 16px | Card internal padding (`p-4`), form field horizontal gap (`gap-4`) |
| lg | 24px | Page section gap (`space-y-6`), stat grid gap (`gap-4`) |
| xl | 32px | Page vertical padding (`py-8`) |
| 2xl | 48px | Empty state vertical padding (`py-16` = 64px — see exception) |
| 3xl | 64px | Not used in admin surface |

**Exceptions:**
- Empty state cell: `py-16` (64px) — matches existing `AffiliatesTable` empty row treatment.
- Card thumbnail container: `aspect-video` with `w-full` — dimensions are ratio-driven, not fixed pixel spacing.

### Per-Card Edit Panel

Opened by clicking "Edit" on a card. Implemented as an inline expander below the card controls (not a modal — keeps the page layout predictable and avoids z-index stacking context issues with the sticky header).

The edit panel replaces the card's controls row with an edit form when `editingId === row.id`. The rest of the card (thumbnail, title) remains visible above.

```
{editingId === row.id && (
  <form onSubmit={handleEdit} className="mt-2 space-y-4 border-t border-gray-100 pt-4">
    ...fields...
    <div className="flex gap-2">
      <button type="submit" disabled={busyId === row.id}
        className="rounded-lg bg-green-700 px-3 py-2 text-xs font-bold text-white hover:bg-green-800 disabled:opacity-50 transition-colors">
        {busyId === row.id ? 'Saving…' : 'Save changes'}
      </button>
      <button type="button" onClick={() => setEditingId(null)}
        className="rounded-lg border border-gray-300 bg-white px-3 py-2 text-xs font-normal text-gray-700 hover:bg-gray-50 transition-colors">
        Discard changes
      </button>
    </div>
  </form>
)}
```

**Edit fields:**

| Field | Type | Required | Label copy |
|-------|------|----------|------------|
| Title | text | Yes | `TITLE *` |
| Description | textarea (2 rows) | No | `DESCRIPTION` |
| Caption | textarea (3 rows) | No | `CAPTION` |
| Active | checkbox or toggle | — | `ACTIVE` |

Asset file is not editable in the edit panel. No file input appears. A note below the panel reads: `<p className="text-xs text-gray-400">To replace the asset, delete this creative and upload a new one.</p>`

Active toggle in edit panel: render as `<input type="checkbox">` styled with `h-4 w-4 rounded border-gray-300 text-blue-600 focus:ring-blue-500` (shadcn Checkbox or bare input — use bare input to avoid adding a new shadcn component for a single boolean field).

## Interaction States

### Busy State

When any mutation is in flight for a card (`busyId === row.id`), ALL controls on that card are `disabled`. The button that triggered the action may show a loading label (e.g. "Saving…") or remain labeled but visually disabled (`opacity-50`). Only one card can be busy at a time (tracked by `busyId: string | null`).

### Upload State

During upload (`uploading === true`):
- Submit button shows "Uploading…" and is `disabled`.
- Progress bar is visible.
- Panel form fields remain visible (not disabled) — allows review while upload runs.
- "Close" / cancel is NOT disabled during upload; clicking it does not cancel the in-flight upload (no abort controller needed for v1 — matches simplicity-first scope).

### Reorder Boundary State

- First card in the sorted list: ▲ button is `disabled`.
- Last card: ▼ button is `disabled`.
- Reorder is silent (no flash notice) — the grid reorders immediately after `router.refresh()`.

### Edit Open State

- Only one card can be in edit mode at a time (`editingId: string | null`).
- Opening edit on a second card auto-closes the first (set `editingId` to the new id).
- Edit panel is not a modal — it is inline within the card, below the controls row.

## Responsive Behavior

| Breakpoint | Grid columns | Inline panel layout |
|------------|-------------|---------------------|
| Default (mobile) | 1 | Single-column stacked fields |
| `sm` (640px+) | 2 | Two-column field grid (`grid-cols-2 gap-4`) |
| `lg` (1024px+) | 3 | Two-column field grid (unchanged) |

Card controls (`flex flex-wrap gap-2`) wrap naturally on narrow cards. ▲▼ Edit Activate Delete all appear on one line at `lg` card width (~380px); they wrap to two lines at `sm` card width (~280px). This is acceptable — no control is hidden.

Admin is desktop-optimized. Mobile is functional but not the primary concern.

## Accessibility Notes

- All icon-only buttons (▲▼) must have `aria-label`: `aria-label="Move up"` / `aria-label="Move down"`.
- Delete button: `aria-label={`Delete ${row.title}`}`.
- File inputs: associated `<label>` via `htmlFor` + `id` pair.
- Progress bar: `role="progressbar" aria-valuenow={progress} aria-valuemin={0} aria-valuemax={100}`.
- Flash notices: `role="status"` or `aria-live="polite"` on the notice container.
- Active/inactive badge is decorative; the toggle button's label conveys state.
