<objective>
Build the server-side API layer for admin creative management: a Vercel Blob client-upload token route, a collection route (list + create-row-after-upload), and an item route (metadata edit, active toggle, reorder swap, delete). Consumes the Phase 1 data layer `src/lib/creatives.ts` directly — no schema or migration changes.

Purpose: These guarded endpoints are the only way the admin UI (Plan 02) mutates creatives. The token route lets large videos upload directly to Vercel Blob, bypassing the ~4.5MB serverless body limit (ADMIN-02).
Output: Three route handler files under `src/app/api/admin/creatives/`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser → upload-token route | Untrusted client requests a signed blob token; only authenticated admins may receive one |
| admin browser → Vercel Blob CDN | Direct file transfer using the signed token; content-type and size are enforced by the token's constraints |
| admin browser → collection/item routes | Untrusted JSON body crosses here to create/mutate/delete DB rows and trigger blob deletion |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Elevation of Privilege | upload-token/route.ts onBeforeGenerateToken | mitigate | `isAdminAuthenticated()` checked at handler entry AND re-checked inside `onBeforeGenerateToken` (throws if false) — defense-in-depth per ASVS V2/V4 |
| T-02-02 | Tampering | upload-token/route.ts allowedContentTypes | mitigate | `allowedContentTypes` restricted to `[...ACCEPTED_IMAGE_MIME, ...ACCEPTED_VIDEO_MIME]` from creatives.ts; client-declared type cannot widen it (ASVS V5) |
| T-02-03 | Denial of Service | upload-token/route.ts maximumSizeInBytes | mitigate | `maximumSizeInBytes: MAX_CREATIVE_BYTES` (200MB) enforced by the signed token; oversized uploads rejected by Vercel Blob, not trusted from client |
| T-02-04 | Elevation of Privilege | route.ts POST / [id] PATCH+DELETE | mitigate | Every handler calls `isAdminAuthenticated()` first and returns 401 otherwise; no unauthenticated caller can create/mutate/delete a creative or trigger blob deletion |
| T-02-05 | Tampering | route.ts POST mimeType field | mitigate | Server re-validates `mimeType` against the shared MIME constants and derives `type` server-side; never trusts a client-declared `type` field |
| T-02-06 | Information Disclosure (storage waste) | two-step upload (orphaned blob if row POST fails) | accept | Two-step upload has an inherent TOCTOU gap; the client logs the orphaned `blobPath` for manual cleanup and the short token TTL bounds exposure. Marketing assets, no PII — low value (RESEARCH Pitfall 2) |
| T-02-07 | Tampering | blob path enumeration | mitigate | `addRandomSuffix: true` makes stored pathnames non-predictable; clients never control the final path |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed this phase; `@vercel/blob` 2.4.0 was audited and approved in Phase 1 (RESEARCH Package Legitimacy Audit). No [ASSUMED]/[SUS] packages |
</threat_model>
