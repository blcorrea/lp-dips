<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser → upload-token route | Client requests a signed token via `upload()`; handled by the Plan 02-01 route which enforces auth + MIME/size |
| admin browser → Vercel Blob CDN | Direct file transfer; constrained by the signed token issued server-side |
| admin browser → collection/item routes | JSON mutations to create/edit/reorder/delete; all guarded server-side in Plan 02-01 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-08 | Spoofing | CreativesGrid mutation fetches | mitigate | All mutations call the Plan 02-01 routes which re-check `isAdminAuthenticated()` server-side; the client component never holds privileged secrets and the page is reachable only behind the admin layout auth gate |
| T-02-09 | Tampering | client-side MIME/size validation | mitigate | Client validation is UX-only and reuses the shared constants; the upload-token route + collection POST re-validate server-side (client checks are not trusted) |
| T-02-10 | Information Disclosure (storage waste) | orphaned blob if row POST fails after upload() | accept | `console.error` logs the orphaned `blobPath`; marketing assets, no PII; accepted per RESEARCH Pitfall 2 (orphaned row > orphaned blob is the project preference) |
| T-02-11 | Repudiation | destructive delete without confirmation | mitigate | Native `confirm()` gate before DELETE (D-09); server delete is idempotent (no-ops on missing row) |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new packages this phase; `@vercel/blob` already approved in Phase 1. `@vercel/blob/client` and `lucide-react` are existing dependencies |
</threat_model>
