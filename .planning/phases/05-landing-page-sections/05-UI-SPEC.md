# Phase 5 — UI Design Contract

> Visual and interaction contract for the 8 redesigned home-page sections (trust bar/header, hero, story, ingredients, bundle selector, reviews, FAQs, footer). Consumes all tokens/fonts/CTA-orange from Phase 4 (`04-UI-SPEC.md`, already implemented in `src/app/globals.css`) — **no new design tokens are introduced this phase.** Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Source of truth for all raw Figma values:** `.planning/phases/05-landing-page-sections/FIGMA-EXTRACTION.md` (recovered from a prior session's scratchpad during this research pass — Phase 4 was supposed to copy it into the repo and didn't; only the 27 image assets made it into `public/images/redesign/`). Every measurement/copy citation below traces to that document.

**User decisions confirmed this session** (no CONTEXT.md existed for this phase — asked directly):

1. Fold `ProductSection`'s 4 features into Hero's feature-card row; drop `WhyDipsSection` entirely (no Figma counterpart in the 8-section list).
2. Header nav is exactly Figma's 4 anchors + CTA — drop the EN/ES/PT switcher, social icons, and inline Affiliates link from the header. "Menu" anchors back to the hero/top of page.
3. Trust bar copy: "100% Natural Ingredients · Made in the USA · Secure Checkout · Discreet Packaging · Aphrodisiac Blend · 10,000+ Happy Couples".
4. Reviews masonry: 3 columns from `md` breakpoint up (drop the current `lg:columns-4` step), still 2 columns below `md`.
5. FAQ: keep the existing real Q&A copy (`FAQ.q1..q6`/`a1..a6`, already translated en/es/pt) verbatim; only the container/interaction is redesigned (shadcn `accordion.tsx`, orange border + rotated chevron on the open item).

## Architectural Decision — Header/Footer must NOT be edited in place

**Finding during research:** `src/components/Header.tsx` and `src/components/Footer.tsx` are shared layout components imported by **9 pages**, not just the home page: `product/[slug]`, `products`, `orders`, `orders/[id]`, `profile`, `wishlist`, `checkout/success`, `[locale]/page.tsx` (home), and `LegalPageLayout.tsx` (privacy/terms/shipping/returns). REQUIREMENTS.md's `FUNC-03` explicitly requires **order confirmation** (`checkout/success`) to stay visually unchanged, and only `SECT-01`/`SECT-08` (scoped to "the home") ask for a redesigned header/footer.

**Locked decision:** Phase 5 must **not** modify `Header.tsx`/`Footer.tsx` in place. Instead:
- New `LandingHeader.tsx` (trust bar + minimal nav, SECT-01) and `LandingFooter.tsx` (SECT-08) are added and used **only** in `src/app/[locale]/page.tsx`.
- The existing `Header.tsx`/`Footer.tsx` continue to serve all 8 other pages unchanged — protecting `FUNC-03` and avoiding scope creep onto pages not named in `SECT-01..08`.
- This mirrors Phase 4's own precedent of an additive `--color-dips-*` namespace kept separate from `--color-brand-*` for exactly the same isolation reason.

Planner/executor: treat this as a structural constraint, not a suggestion — reusing `Header`/`Footer` for the home page is the wrong outcome even though it looks like less code.
