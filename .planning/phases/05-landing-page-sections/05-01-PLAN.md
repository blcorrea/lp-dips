<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| i18n message → rendered DOM | Locale JSON strings are interpolated into JSX text |
| newsletter form → (no backend this phase) | Email input is client-only (existing Footer behavior); no new network write |
| footer links → external targets | mailto:/tel: and internal route Links |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Injection (XSS) | LandingHeader/LandingFooter i18n text | mitigate | Render all copy via next-intl `{t(...)}` JSX text nodes only; no `dangerouslySetInnerHTML`, no `t.markup`/raw HTML for these strings |
| T-05-02 | Tampering | Footer external anchors | mitigate | mailto:/tel: are static literals; no `target="_blank"` opener leak (if any `_blank` is used, include `rel="noopener noreferrer"`) |
| T-05-03 | Information disclosure | Footer contact/address | accept | Publishing the real business support email/address is intended public info (already live in Footer.tsx) |
| T-05-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs this plan (all UI primitives already present); no supply-chain surface added |
</threat_model>
